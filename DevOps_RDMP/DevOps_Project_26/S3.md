Project: Static Website Hosting Using Amazon S3

## Project Overview

I hosted a static website using **Amazon S3** by configuring bucket permissions, enabling static website hosting, and applying a secure bucket policy to allow public read access.

---
![alt text](<DevOps_RDMP/DevOps_Project_26/S3.png>)

## What I Did in This Project (Professional Way)

### 1. Created an S3 Bucket

* Created an Amazon S3 bucket with a **globally unique name**
* Selected the appropriate AWS region

**Why:**
S3 provides highly durable and scalable object storage suitable for static websites.

---

### 2. Uploaded Website Files

* Uploaded `index.html`, CSS, JavaScript, and image files into the bucket

**Why:**
S3 serves static content directly without requiring a server.

---

### 3. Enabled Static Website Hosting

* Enabled **Static Website Hosting** in bucket properties
* Configured:

  * **Index document**: `index.html`
  * (Optional) **Error document**: `error.html`

**Why:**
This allows S3 to behave like a web server and generate a website endpoint URL.

---

### 4. Managed Public Access Settings

* Disabled **Block Public Access** at bucket level (only for this use case)

**Why:**
Public access is required for users to view the website via a browser.

---

### 5. Configured Bucket Policy

* Applied an **S3 Bucket Policy** to allow public read access

**Policy Objective:**

* Allow `s3:GetObject`
* Principal: `*` (public)
* Resource: All objects in the bucket

**Why:**
Ensures users can access website files securely and intentionally.

---

### 6. Accessed the Website

* Used the **S3 static website endpoint URL** to access the hosted website

---

# Interview Questions & Easy Professional Answers

---

### 1. What is Amazon S3?

**Answer:**
Amazon S3 is an object storage service that provides scalable, durable, and highly available storage for data such as files, images, and static websites.

---

### 2. Why did you use S3 for hosting a static website?

**Answer:**
S3 is cost-effective, serverless, highly available, and ideal for hosting static content without managing servers.

---

### 3. What is static website hosting in S3?

**Answer:**
Static website hosting allows S3 to serve HTML files directly to users using a website endpoint.

---

### 4. Why did you disable “Block Public Access”?

**Answer:**
Public access is required so users can access the website files through a browser.

---

### 5. What is an S3 bucket policy?

**Answer:**
A bucket policy is a JSON-based access control policy that defines who can access the bucket and what actions they can perform.

---

### 6. What action did you allow in the bucket policy?

**Answer:**
I allowed the `s3:GetObject` action so users can read website files.

---

### 7. What is the role of `index.html`?

**Answer:**
`index.html` is the default landing page displayed when users access the website.

---

### 8. Is hosting a website on S3 secure?

**Answer:**
Yes, when permissions are carefully configured and access is limited to required actions only.

---

### 9. Can S3 host dynamic websites?

**Answer:**
No, S3 supports only static content. Dynamic websites require services like EC2 or Lambda.

---

### 10. How can you make the S3 website more secure?

**Answer:**
By using:

* CloudFront
* HTTPS (SSL)
* Restricting bucket access via policies

---

### 11. Difference between S3 and EC2 hosting?

| S3          | EC2              |
| ----------- | ---------------- |
| Serverless  | Requires server  |
| Low cost    | Higher cost      |
| Static only | Static + dynamic |

---

### 12. What happens if bucket name is not unique?

**Answer:**
S3 will not allow creation because bucket names must be globally unique.
